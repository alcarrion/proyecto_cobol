                            1. VISIÓN GENERAL
================================================================================

El proyecto es un SISTEMA BANCARIO INTEGRADO que gestiona:
  • Clientes (Alta, Baja, Modificación, Consulta)
  • Cuentas Corrientes (Depósitos, Extracciones, Consultas de Saldo)
  • Tarjetas de Crédito (Emisión, Consumos, Pagos, Bloqueos)
  • Hipotecas/Préstamos (Altas, Pagos de Cuotas, Consultas)
  • Transacciones Bancarias (Commit/Rollback)

ARQUITECTURA: 3 Capas
  1. PRESENTACIÓN: Programas MAINLINE (CI0000, IN0000, TC0000, BR0000, BAT000)
  2. LÓGICA DE NEGOCIO: Reglas y validaciones en MAINLINE
  3. ACCESO A DATOS: Módulos DBIO (DBIOCUSM, DBIOINVM, DBIOTARJ, DBIOBORM)

TECNOLOGÍA BD: 
  - Driver: MySQL ODBC 8.0 ANSI Driver
  - Servidor: localhost
  - Database: proyecto_cobol
  - Usuario: root / Password: tata

┌─────────────────────────────────────────────────────────────────────────────┐
│ B) CI0000.cbl (MÓDULO CIF - GESTIÓN DE CLIENTES)
├─────────────────────────────────────────────────────────────────────────────┤
│ FUNCIONALIDAD: ABM de Clientes (Alta, Baja, Modificación, Consulta)
│
│ OPERACIONES:
│   1. ALTA DE CLIENTE (2000-ALTA-CLIENTE)
│      - Valida tipo de documento (CED/PAS)
│      - Verifica que no exista cedula duplicada (CONSULTA a DBIOCUSM)
│      - Captura: Nombre, Apellidos, Dirección, Teléfono, Email
│      - Inicializa: saldo=0, tarjeta=0, crédito=0, hipoteca=0, cta_activa=1
│      - INSERTA Cliente en DBIOCUSM (acción 'A')
│      - INSERTA Cuenta Corriente en DBIOINVM (acción 'A')
│      - Genera COMMIT si ambas operaciones exitosas
│
│   2. CONSULTA DE CLIENTE (3000-CONSULTA-CLIENTE)
│      - Busca cliente por documento
│      - Llama DBIOCUSM con acción 'C' (consulta)
│      - Devuelve datos del cliente si existe
│
│   3. MODIFICACIÓN DE CLIENTE (4000-MODIFICA-CLIENTE)
│      - Busca cliente por documento
│      - Permite actualizar: Dirección, Teléfono, Email
│      - Llama DBIOCUSM con acción 'M' (modificación)
│
│   4. BAJA LÓGICA (5000-BAJA-CLIENTE)
│      - Busca cliente por documento
│      - Marca CTA_ACTIVA = 0 y setea FECHA_CIERRE = CURDATE()
│      - Llama DBIOCUSM con acción 'B' (baja)
│
│ ESTRUCTURAS DE DATOS:
│   - REG-CUSM: Registro de cliente (copybook CUSMREC)
│   - REG-INVM: Registro de cuenta corriente (copybook INVMREC)
│   - LK-DATOS-TRANSACCION: Control de transacción (copybook LKCIF)
│
│ QUERIES (delegadas a DBIOCUSM):
│   SELECT: Busca cliente por DOC_CLIENTE
│   INSERT: Inserta nuevo cliente
│   UPDATE: Actualiza dirección, teléfono, email o marca baja
│
│ FLOW: Menú → Opción → Validaciones → Llamada DBIO → Transacción → Mensaje
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ C) IN0000.cbl (MÓDULO INVM - CUENTAS CORRIENTES)
├─────────────────────────────────────────────────────────────────────────────┤
│ FUNCIONALIDAD: Gestión de Cuentas Corrientes (Depósitos, Extracciones)
│ REGLA CRÍTICA: No permitir saldo negativo
│
│ OPERACIONES:
│   1. CONSULTA DE SALDO (2000-CONSULTA-SALDO)
│      - Busca cliente por documento (DBIOCUSM 'C')
│      - Obtiene ID_CLIENTE
│      - Consulta saldo en DBIOINVM ('C')
│      - Muestra saldo actual
│
│   2. DEPOSITO (3000-DEPOSITO)
│      - Busca cliente y cuenta
│      - Acepta monto > 0
│      - Suma monto a SALDO_ACTUAL
│      - Setea COD_ULT_MOV = 2 (código depósito)
│      - Actualiza en DBIOINVM ('M')
│      - Commit si exitoso
│
│   3. EXTRACCIÓN (4000-EXTRACCION)
│      - Busca cliente y cuenta
│      - Valida que monto <= SALDO_ACTUAL (sin negativo)
│      - Resta monto a SALDO_ACTUAL
│      - Setea COD_ULT_MOV = 3 (código retiro)
│      - IMPORTE_MOV = monto * -1 (valor negativo)
│      - Actualiza en DBIOINVM ('M')
│      - Commit si exitoso
│
│ QUERIES:
│   INSERT: Crea registro en CTACTES al dar de alta cliente
│   SELECT: Obtiene saldo actual por ID_CLIENTE
│   UPDATE: Actualiza saldo, código movimiento e importe
│
│ VALIDACIONES CRÍTICAS:
│   - Cliente debe existir
│   - Cuenta debe existir (se crea con alta de cliente)
│   - No permitir saldo negativo
│   - Monto debe ser > 0
│
│ FLOW: Busca Cliente → Obtiene Cuenta → Valida Monto → Actualiza → Transacción
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ D) TC0000.cbl (MÓDULO TARJETAS - TARJETAS DE CRÉDITO)
├─────────────────────────────────────────────────────────────────────────────┤
│ FUNCIONALIDAD: Gestión de Tarjetas de Crédito
│ REGLAS:
│   - Cliente debe existir y estar activo
│   - Una tarjeta por cliente (máximo)
│   - Tarjeta debe estar Activa para operar
│
│ OPERACIONES:
│   1. EMISIÓN DE TARJETA (2000-EMISION-TARJETA)
│      - Valida que cliente exista y esté activo (DBIOCUSM 'C')
│      - Verifica que cliente no tenga tarjeta (CUSM-TARJETA = 0)
│      - GENERA número dinámico: prefijo '4555' + ID_CLIENTE + random
│      - Calcula FECHA_VENCIMIENTO = fecha_emisión + 4 años
│      - Acepta LIMITE DE CRÉDITO
│      - INSERTA en DBIOTARJ ('A')
│      - ACTUALIZA flag CUSM-TARJETA = 1 en DBIOCUSM ('M')
│      - COMMIT
│
│   2. CONSULTA DE TARJETA (3000-CONSULTA-TARJETA)
│      - Busca por NRO_TARJETA
│      - Muestra: número, estado, límite, deuda acumulada, disponible
│      - Disponible = LIMITE_TARJETA - ACUM_MES
│
│   3. CARGO A TARJETA (4000-CARGO-TARJETA)
│      - Busca tarjeta por número (DBIOTARJ 'C')
│      - Valida que tarjeta esté activa (ESTADO = 'A')
│      - Valida que monto no exceda disponible
│      - Suma monto a ACUM_MES
│      - ACTUALIZA en DBIOTARJ ('M')
│      - COMMIT
│
│   4. PAGO DE TARJETA (5000-PAGO-TARJETA)
│      - Busca tarjeta
│      - Acepta monto a pagar
│      - Resta de LIQUIDACION_MES (abono)
│      - ACTUALIZA en DBIOTARJ ('M')
│
│   5. CONSULTA DE DEUDA (6000-CONSULTA-DEUDA)
│      - Muestra ACUM_MES (consumos)
│      - Muestra LIQUIDACION_MES (pagos)
│      - Calcula deuda pendiente = ACUM_MES - LIQUIDACION_MES
│
│   6. BLOQUEO DE TARJETA (7000-BLOQUEO-TARJETA)
│      - Marca ESTADO = 'B' (Bloqueada)
│
│   7. BAJA/CANCELACIÓN (8000-BAJA-TARJETA)
│      - Valida que deuda esté pagada
│      - Marca ESTADO = 'I' (Inactiva)
│      - ACTUALIZA en DBIOTARJ ('M')
│
│ QUERIES (delegadas a DBIOTARJ):
│   INSERT: Emitir nueva tarjeta
│   SELECT: Consultar por NRO_TARJETA
│   UPDATE: Actualizar límite, deuda, estado
│
│ FLOW: Menú → Opción → Busca Tarjeta → Validaciones → Actualiza → Transacción
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ E) BR0000.cbl (MÓDULO BORM - HIPOTECAS/PRÉSTAMOS)
├─────────────────────────────────────────────────────────────────────────────┤
│ FUNCIONALIDAD: Gestión de Hipotecas y Préstamos
│
│ OPERACIONES:
│   1. ALTA DE PRÉSTAMO (2100-REGISTRAR-ALTA)
│      - Busca cliente por documento (DBIOCUSM 'C')
│      - Valida que cliente exista
│      - GENERA ID dinámico: prefijo '9' + YY + secuencia 6 dígitos
│      - Acepta: Monto del préstamo
│      - Acepta: Tasa de interés anual (ej: 10.5%)
│      - Acepta: Plazo en meses
│      - Calcula FECHA_VENCIMIENTO = fecha_inicio + plazo en meses
│      - Acepta: Día de pago (1-31)
│      - INSERTA en DBIOBORM ('A')
│      - COMMIT
│
│   2. CONSULTA DE HIPOTECA (2200-CONSULTAR-SALDO)
│      - Busca por ID_HIPOTECA
│      - Muestra: saldo actual, fecha vencimiento, estado
│
│   3. PROCESAR PAGO (2300-PROCESAR-PAGO)
│      - Busca hipoteca por ID
│      - Muestra saldo actual
│      - Acepta monto a pagar
│      - Valida que no exceda deuda
│      - Resta del SALDO_ACTUAL
│      - ACTUALIZA en DBIOBORM ('M')
│      - Calcula amortización automática
│
│ QUERIES (delegadas a DBIOBORM):
│   INSERT: Crear nueva hipoteca
│   SELECT: Consultar por ID_HIPOTECA
│   UPDATE: Actualizar saldo_actual y estado
│   ESPECIAL: UPDATE control_secuencias para generar ID único
│
│ FLOW: Menú → Opción → Busca Cliente → Valida → Calcula Vencimiento → 
│       Inserta/Actualiza → Transacción
└─────────────────────────────────────────────────────────────────────────────┘

================================================================================
                    3. MÓDULOS DBIO (CAPA DE ACCESO A DATOS)
================================================================================

Los módulos DBIO implementan CRUD (Create, Read, Update, Delete) con Embedded SQL.
Se comunican vía LINKAGE SECTION con el control de transacción LKCIF.

PATRÓN COMÚN:
  Entrada: Registro de datos + Acción BD + Datos transacción
  Proceso: Ejecuta SQL según acción
  Salida: Código retorno + Mensaje + Registro actualizado

ACCIONES SOPORTADAS:
  'A' = ALTA (INSERT)
  'C' = CONSULTA (SELECT)
  'M' = MODIFICACIÓN (UPDATE)
  'B' = BAJA LÓGICA (UPDATE con estado/fecha cierre)

┌─────────────────────────────────────────────────────────────────────────────┐
│ A) DBIOCUSM (CRUD de CLIENTES)
├─────────────────────────────────────────────────────────────────────────────┤
│ QUERIES IMPLEMENTADAS:
│
│ 1. INSERT - REGISTRAR NUEVO CLIENTE
│    SQL-STMT-0:
│    INSERT INTO clientes (
│        TIPO_DOC, DOC_CLIENTE, FECHA_ALTA, NOMBRE_CLIENTE, APELLIDOS_CLIENTE,

│        TARJETA, CREDITO, HIPOTECA, CTA_ACTIVA, FECHA_CIERRE, SALDO_CLIENTE
│    ) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
│
│ 2. SELECT LAST_INSERT_ID() - OBTENER ID GENERADO
│    SQL-STMT-1:
│    SELECT LAST_INSERT_ID()
│    Retorna ID_CLIENTE generado automáticamente
│
│ 3. SELECT - CONSULTAR POR DOCUMENTO
│    SQL-STMT-2:
│    SELECT ID_CLIENTE, TIPO_DOC, FECHA_ALTA, NOMBRE_CLIENTE,
│           APELLIDOS_CLIENTE, DIRECCION_CLIENTE, TELEF_CLIENTE, EMAIL_CLIENTE,
│           TARJETA, CREDITO, HIPOTECA, CTA_ACTIVA, FECHA_CIERRE, SALDO_CLIENTE
│    FROM clientes
│    WHERE DOC_CLIENTE = ?
│    [1 parámetro: documento del cliente]
│
│ 4. UPDATE - MODIFICAR DATOS CONTACTO

│    UPDATE clientes SET
│        DIRECCION_CLIENTE = ?, TELEF_CLIENTE = ?, EMAIL_CLIENTE = ?

│    [3 parámetros: nuevos datos; 1 parámetro: documento]
│
│ 5. UPDATE - BAJA LÓGICA
│    SQL-STMT-4:
│    UPDATE clientes SET
│        CTA_ACTIVA = 0, FECHA_CIERRE = CURDATE()
│    WHERE DOC_CLIENTE = ?
│    [1 parámetro: documento]
│
│ RETURNS:
│   - LK-COD-RETORNO: 0 = éxito, !=0 = error
│   - LK-MENSAJE: Descripción del resultado
│   - REG-CUSM: Datos del cliente (si consulta exitosa)

┌─────────────────────────────────────────────────────────────────────────────┐
│ E) DBIOTRAN (CONTROL DE TRANSACCIONES)
├─────────────────────────────────────────────────────────────────────────────┤
│ FUNCIONALIDAD:
│   - Manejo de COMMIT y ROLLBACK
│   - Control de integridad transaccional
│
│ OPERACIONES:
│
│ 1. COMMIT
│    Acción: 'C'
│    EXEC SQL COMMIT WORK END-EXEC
│    Confirma todos los cambios de la transacción
│
│ 2. ROLLBACK
│    Acción: 'R'
│    EXEC SQL ROLLBACK WORK END-EXEC
│    Deshace todos los cambios de la transacción
│
│ USO TÍPICO:
│   - Después de operaciones exitosas: CALL 'DBIOTRAN' USING 'C'
│   - Después de errores o validaciones fallidas: CALL 'DBIOTRAN' USING 'R'
│
│ EJEMPLO (CI0000 - Alta de Cliente):
│   MOVE 'A' TO LK-ACCION-DB
│   CALL 'DBIOCUSM' USING REG-CUSM, LK-DATOS-TRANSACCION  [Inserta cliente]
│   IF LK-COD-RETORNO = 0
│       CALL 'DBIOINVM' USING REG-INVM, LK-DATOS-TRANSACCION  [Crea cuenta]
│       IF LK-COD-RETORNO = 0
│           CALL 'DBIOTRAN' USING 'C'  [COMMIT - ambas operaciones OK]
│       ELSE
│           CALL 'DBIOTRAN' USING 'R'  [ROLLBACK - fallo en cuenta]
│       END-IF
│   ELSE
│       CALL 'DBIOTRAN' USING 'R'  [ROLLBACK - fallo en cliente]
│   END-IF
│
│ NOTA: Garantiza la integridad ACID de las transacciones
└─────────────────────────────────────────────────────────────────────────────┘

                        4. COPYBOOKS (ESTRUCTURAS DE DATOS)
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│ A) LKCIF.CPY - CONTROL DE TRANSACCIONES
├─────────────────────────────────────────────────────────────────────────────┤
│ 01  LK-DATOS-TRANSACCION.
│     05 LK-ACCION-DB             PIC X(01).
│        'A'=INSERT, 'B'=DELETE, 'M'=UPDATE, 'C'=SELECT, 'S'=SIGUIENTE
│     05 LK-ID-CLIENTE            PIC 9(09).
│     05 LK-IMPORTE-TRANSACCION   PIC S9(13)V99 COMP-3.
│     05 LK-MODO-OPERACION        PIC X(01).

  - Precompilador: cobc (GnuCOBOL)
  - Driver: MySQL ODBC 8.0 ANSI Driver
  - Lenguaje: COBOL + SQL embebido (EXEC SQL ... END-EXEC)
  - Parámetros: Placeholders (?) - Prepared Statements

MANEJO DE ERRORES SQL:
  - SQLCODE: Código de retorno SQL
    0 = Éxito
    != 0 = Error (consultar SQLERRMC para detalle)
  - SQLSTATE: Estado SQL estándar (5 caracteres)
    '00000' = Success
    '02000' = No data (sin registros)
    '23000' = Violación de integridad (PK/FK)
    '24000' = Invalid cursor state
  - SQLERRMC: Mensaje de error descriptivo

ESTRUCTURA DE CONTROL SQLCA (SQL Communications Area):
  - SQLCODE: Código numérico del error
  - SQLSTATE: Estado estándar
  - SQLERRM: Mensaje de error
  - SQLERRD: Array de 6 valores diagnósticos

CREATE DATABASE IF NOT EXISTS proyecto_cobol;
USE proyecto_cobol;

-- 1. TABLA: INDICADORES (Mapeo de tabla SYSC en el diagrama)
-- Es una tabla independiente de configuración.
CREATE TABLE IF NOT EXISTS INDICADORES (
    CODIGO VARCHAR(10) PRIMARY KEY,
    VALOR DECIMAL(10,4),
    DESCRIPCION VARCHAR(50)
);

-- 2. TABLA: COD_MOVIMIENTOS (Mapeo de tabla ED1P en el diagrama)
-- Catálogo de tipos de movimientos (+ o -).
CREATE TABLE IF NOT EXISTS COD_MOVIMIENTOS (
    CODIGO INT(2) PRIMARY KEY,
    DESCRIPCION VARCHAR(30),
    TIPO_AFECTACION CHAR(1) -- '+' o '-'
);

-- 3. TABLA: clientes (Mapeo de tabla CUSM en el diagrama)
-- Tabla principal de la cual dependen las demás.
CREATE TABLE IF NOT EXISTS clientes (
    ID_CLIENTE INT(8) PRIMARY KEY,
    TIPO_DOC VARCHAR(3),
    DOC_CLIENTE VARCHAR(12),
    FECHA_ALTA DATE,
    NOMBRE_CLIENTE VARCHAR(25),
    APELLIDOS_CLIENTE VARCHAR(25),
    DIRECCION_CLIENTE VARCHAR(45),
    TELEF_CLIENTE VARCHAR(12),
    EMAIL_CLIENTE VARCHAR(40),
    TARJETA TINYINT(1),
    CREDITO TINYINT(1),
    HIPOTECA TINYINT(1),
    CTA_ACTIVA TINYINT(1),
    FECHA_CIERRE DATE,
    SALDO_CLIENTE DECIMAL(12,2)
);

-- 4. TABLA: TARJETAS (Mapeo de tabla TARJ en el diagrama)
-- Relación Posee (1:N) -> Un cliente puede tener varias tarjetas.
CREATE TABLE IF NOT EXISTS TARJETAS (
    ID_CLIENTE INT(8),
    NRO_TARJETA VARCHAR(16),
    FECHA_EMISION DATE,
    FECHA_VENCIMIENTO DATE,
    LIMITE_TARJETA DECIMAL(12,2),
    ACUM_MES DECIMAL(12,2),
    LIQUIDACION_MES DECIMAL(12,2),
    ESTADO CHAR(1),
    PRIMARY KEY (ID_CLIENTE, NRO_TARJETA),
    CONSTRAINT FK_TARJETAS_CLIENTE FOREIGN KEY (ID_CLIENTE) 
        REFERENCES clientes(ID_CLIENTE) ON DELETE CASCADE
);

-- 5. TABLA: ctactes (Mapeo de tabla INVM en el diagrama)
-- Relación Tiene (1:1 Obligatorio) -> Un registro por cliente.
-- Relación Registra Tipo (N:1) -> Apunta al catálogo de movimientos.
CREATE TABLE IF NOT EXISTS ctactes (
    ID_CLIENTE INT(8) PRIMARY KEY,
    COD_ULT_MOV INT(2),
    FECHA_ULT_MOV DATE,
    IMPORTE_MOV DECIMAL(12,2),
    SALDO_ACTUAL DECIMAL(12,2),
    CONSTRAINT FK_CTACTES_CLIENTE FOREIGN KEY (ID_CLIENTE) 
        REFERENCES clientes(ID_CLIENTE) ON DELETE CASCADE,
    CONSTRAINT FK_CTACTES_MOVIMIENTO FOREIGN KEY (COD_ULT_MOV) 
        REFERENCES COD_MOVIMIENTOS(CODIGO)
);

-- 6. TABLA: HIPOTECAS (Mapeo de tabla BORM en el diagrama)
-- Relación Mantiene (1:N) -> Un cliente puede tener múltiples préstamos hipotecarios.
CREATE TABLE IF NOT EXISTS HIPOTECAS (
    ID_HIPOTECA INT(9) PRIMARY KEY,
    ID_CLIENTE INT(8), -- Cambiado a INT(8) para coincidir con el PK de Clientes
    FECHA_INICIO DATE,
    MONTO_ORIGINAL DECIMAL(15,2),
    TASA_INTERES DECIMAL(7,4),
    SALDO_ACTUAL DECIMAL(15,2),
    FECHA_VENCTO DATE,
    DIA_PAGO INT(2),
    ESTADO VARCHAR(20),
    CONSTRAINT FK_HIPOTECAS_CLIENTE FOREIGN KEY (ID_CLIENTE) 
        REFERENCES clientes(ID_CLIENTE) ON DELETE CASCADE
);
